# Android device check

The automated browser tests emulate phone and tablet screen sizes; they do not verify Android hardware or an installed app. Run this check on the intended phone and tablet. Record each device model, Android and Chrome versions, date, orientation and any problems, including the exact action and visible message. Check desktop separately with a mouse and keyboard.

1. **Set up online.** Open the play site in Chrome and allow its bundled files to load. Confirm **Play Lemmings** and the offline-readiness message appear. Windows should be selected initially when its files are present. Choose DOS and then Windows and confirm each shows its own levels and saved results; an explicit choice should be remembered. Windows can run with only the Windows files. If testing manual import, use the file-free preview, choose **Add Windows files** and select the compatible Windows ISO, or **Add DOS files** and select the original DAT files or a ZIP. Each site has separate browser storage.
2. **Install.** In Chrome, choose **Install app** or **Add to Home screen**, then open the app from its icon. Check it opens independently and sees the same files. Confirm the mode and level selection are legible in portrait and landscape.
3. **Play.** Start a level in Windows mode. Try selecting skills and tapping lemmings, dragging to pan, zooming in and out, and **Reset zoom**. Open **Show a hint**, reveal another and try **Show example first move**; the example describes a verified route, not the current attempt. Complete a level and check the saved result after reopening. Repeat a representative level in DOS mode if both editions are available.
4. **Fullscreen and interruptions.** Enter **Fullscreen** in portrait and landscape. While playing, confirm there are no floating controls over the level and that the panel’s **NEED** target stays readable next to **OUT**, **IN** and **TIME**. Tap the hourglass pause button on the original bottom panel, immediately left of the red nuke button; check the pause menu opens without also activating another control. Try zoom and reset, **Resume**, **Restart level**, **Level selection** and **Exit fullscreen**. Check the system Back gesture and the expanded-view fallback if native fullscreen is unavailable. Switch apps or lock the screen during play and immediately after starting; return and confirm the game is paused until resumed.
5. **Sound.** Turn Music and Sound on separately. Listen for music and Windows voices/effects, including after pause, resume, locking and reopening. Check speaker and headphones if available, along with volume and silent mode. Music and sound start off by default; Windows MIDI instrumentation is an approximation.
6. **Offline and backup.** While online, wait for the offline-readiness message and load a level. Close the installed app, enable airplane mode, reopen it and start that level. Re-enable connectivity. Export a backup, restore it on the other device, and check progress and the last level for both editions. Restoring replaces existing progress/settings on that device, not its game files; it does not sync automatically.
7. **Updates and recovery.** After an update, reopen online, confirm the selected edition and progress remain, then check an offline relaunch. Do not clear site data as the first fix: it removes locally stored game files and progress. Record failures first. If deliberately testing file removal, confirm **Remove DOS files** or **Remove Windows files** removes only that edition and that automatic bundling does not silently re-import deliberately removed files after reload. Manual import should still work.

A public deployment that bundles original game files makes them downloadable to anyone who can access it. The standard build and file-free preview contain none. The app's browser storage can be cleared or evicted, and the exported backup does not contain game files, so keep a separate copy of the originals.
